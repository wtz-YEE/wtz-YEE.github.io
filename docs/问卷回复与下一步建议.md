## 四、下一步建议

### 建议主轴：做「第二批・成长闭环」，并把它包装成"养成"

理由链条：

1. 他是**每天来**的用户，签到和谜题每天都在给他积分——
   **积分只进不出是个悬空的数字**，补上商店立刻就有获得感，改造量却很小。
2. 他 Q3 明确要**养成**。宠物养成正好是成长闭环的天然出口，
   做在积分之上，不用新开一套系统。
3. 他 Q4 想要**探索感**，但探索感第一批已经给过了。
   第二轮探索感应该建立在"有东西可解锁"之上——
   **有奖励的探索才叫探索，没奖励的叫逛**。
4. 他 Q3 要**界面美化**，这块最省力、最快见效，适合当作**先落地的甜头**给用户看到反馈。
5. **联机放最后**。不是不重要，而是它最重：需要 WebSocket/轮询、
   房间与状态同步、断线处理，而现在后端是 Flask + JSON 文件 +
   cpolar 内网穿透，做实时联机的风险与工期都远高于其他项。
   而且现在**用户量还小**，联机最大的痛点是"没人一起玩"。

### 建议的分批顺序

| 批次 | 内容 | 量级 | 为什么这个顺序 |
|---|---|---|---|
| **第 1 步·先给甜头** | 界面美化 / 新增主题（他明确点名） | S | 最快见效，先让他看到"我提的意见真的被做了" |
| **第 2 步·兑现积分** | 积分商店 + 称号可兑换（头像框 / 主题 / 徽章） | M | 积分已经在攒，补上出口，闭环立刻成立 |
| **第 3 步·养成落地** | 宠物养成：签到/谜题/游戏喂养成，宠物给加成 | M–L | 他 Q3 点名；建在积分与签到之上，复用现有数据 |
| **第 4 步·探索加深** | 世界碎片收集 + 站点迷雾地图 + 干员图鉴收集 | M | 他 Q4 的"探索感"，升级为"可解锁的探索" |
| **第 5 步·社交放大** | 成就墙 / 排行榜 / 好友关注 → 最后才是联机 | M → L | 联机最重，等用户量起来、且有前四步留存的用户再接 |

### 落地时的技术注意（重要）

1. **`users.json` 会加新字段**（积分消耗、宠物、已解锁物品）。
   `_gb` / `_cloud` 的**云端同步合并逻辑必须一起改**：现在 `_merge_users`
   只合并 `exp / is_root / is_admin / checkin / bio / ach / avatar`，
   新字段不进去，**同步时会被对方覆盖丢数据**。
2. **一律走 `_save()` 原子写**（见 `项目易错清单.md` 第 2 条），
   别自己 `open(...,"w")` + `json.dump`。
3. 积分/宠物的数值计算放**服务端**，前端只显示，
   否则改一下 localStorage 就能刷积分。
4. 新增页面记得：单文件自包含、走 `assets/` 相对路径、
   底部 `wNav` 导航与 `wz_map_*` 点亮要接上（否则站点地图会漏节点）。
